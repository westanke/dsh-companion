# 架构决策记录（decisions）

> 每条决策一份文件，格式照 `dsh-remote-bridge/docs/project/decisions/` 的既有体例：
> `ADR-XXXX-短名.md`，头部写状态与日期，正文写**决策**与**原因**。
>
> 姊妹仓库 `dsh-remote-bridge` 已有 7 条（`ADR-0001` 独立外置插件 → `ADR-0007` 图片交接路由），
> 那是服务端侧的账；本目录是 **App 侧**的账，从 `ADR-0100` 起编号，避免与 bridge 侧撞号。

## 为什么 App 侧要单独建这个目录

bridge 侧的 `decisions/` 已经证明了价值：一条「独立外置插件」的决策（`ADR-0001`），
把「不修改 DSH 上游源码、靠 bundle/client 双侧扩展」这个边界钉死，后面所有取舍都有据可查。

App 侧的决策此前散落在三处：`ARCHITECTURE.md`（散文）、`CHANGELOG-DEV.md`（按版本流水）、
`STATUS.md`（当前状态）。**没有一处回答「为什么当初选 A 不选 B」。**
